### ⚠️ The Gemini key is not in this project (found 2026-08-20)

The photography pipeline's Gemini calls — image generation on `nbp_pro` / `nbp_flash`, and
every QA vision judgement — read their key from the environment, but
`skingenetix-website/.env` **contains no Gemini key of any name**. The working key is
`GOOGLE_AI_API_KEY` in the _sister brand's_ file,
`~/Claude Code/Projects/hairgenetix/.env`.

The two consumers disagree about the name, which is what makes this bite quietly:

| Consumer                  | Reads                                  | Behaviour when unset                        |
| ------------------------- | -------------------------------------- | ------------------------------------------- |
| `qa.py` (vision judging)  | `GEMINI_API_KEY` → `GOOGLE_AI_API_KEY` | Every judgement returns a bare `HTTP 400`   |
| `backends.py` (image gen) | `GEMINI_API_KEY` only                  | Backend fails with `GEMINI_API_KEY not set` |

A QA pass run with only this project's `.env` sourced returned **177 errors in seconds** and
looked like a quota problem. It was not: `HTTP 400` was `API_KEY_INVALID`, because the
retry wrapper records `HTTP {code}` and discards the response body. Until the key is added
here from Bitwarden, anything touching Gemini must source **both** files and export
`GEMINI_API_KEY="${GEMINI_API_KEY:-$GOOGLE_AI_API_KEY}"` — the queued top-ups included,
since generation accepts only the first name.
